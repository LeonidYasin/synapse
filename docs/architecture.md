## 2. Блок 1: Извлечение

### 2.1 Токенизация и NER

**Вход:** текст сообщения пользователя  
**Выход:** список токенов + размеченные сущности

| Тип сущности | Пример |
|--------------|--------|
| `PERSON` | Иван, Мария |
| `ORG` | Google, Ethereum Foundation |
| `TECH` | Solidity, React, Rust |
| `TERM` | децентрализация, арбитраж, верификация |
| `PROBLEM` | «я хочу решить проблему доверия» |
| `SOLUTION` | «предлагаю смарт-контракты» |

**Алгоритм:** используется предобученная NER-модель (spaCy, BERT) с дообучением на корпусе крипто/стартап-терминов.

### 2.2 Извлечение интересов

**Алгоритм:** сопоставление с категориальной моделью (дерево категорий).
Категории:
├── Технологии
│ ├── Блокчейн
│ │ ├── DeFi
│ │ ├── NFT
│ │ └── Смарт-контракты
│ ├── Искусственный интеллект
│ └── Разработка
├── Бизнес
│ ├── Стартапы
│ ├── Инвестиции
│ └── Маркетинг
└── Социальное
├── Образование
└── Сообщество

text

**Пример:**  
Текст: «Я увлекаюсь децентрализованными финансами и смарт-контрактами»  
Результат: `interests = ["DeFi", "Смарт-контракты"]`

### 2.3 Извлечение идей

**Алгоритм:** поиск паттернов «проблема → решение».

**Пример:**  
Текст: «Мне кажется, что текущие маркетплейсы слишком дорогие. Можно сделать протокол с комиссией 1% и арбитражем на Шеллинге»  
Результат: `idea = { problem: "высокие комиссии маркетплейсов", solution: "протокол с комиссией 1% + арбитраж Шеллинга" }`

### 2.4 Извлечение потребностей

**Алгоритм:** поиск маркеров («ищу», «нужен», «хочу найти», «помогите»).

**Пример:**  
Текст: «Ищу CTO для стартапа по децентрализованному арбитражу»  
Результат: `need = { role: "CTO", context: "децентрализованный арбитраж" }`

### 2.5 Извлечение экспертизы

**Алгоритм:** сопоставление с базой навыков + частота упоминаний.

**Пример:**  
Текст: «Я 5 лет занимаюсь разработкой на Solidity и React»  
Результат: `expertise = [{ skill: "Solidity", level: 5 }, { skill: "React", level: 5 }]`

## 3. Блок 2: Оценка

### 3.1 Оценка новизны

- **Алгоритм:** косинусное сходство между вектором идеи (Sentence-BERT) и векторами существующих идей в базе.
- **Порог:** `similarity < 0.7` → новизна высокая.
- **Шкала:** `novelty_score ∈ [0, 1]`.

### 3.2 Оценка сложности

- **Алгоритм:** анализ текста на наличие технических терминов, упоминание сложных концепций, количество зависимостей.
- **Шкала:** `complexity_score ∈ [0, 1]`.

### 3.3 Оценка реализуемости

- **Алгоритм:** проверка наличия всех необходимых компонентов (команда, технологии, ресурсы).
- **Пример:**  
  Идея: «децентрализованный маркетплейс»  
  Требования: `[Solidity, IPFS, The Graph, DAO]`  
  Проверка: есть ли в профиле автора эти навыки? Если нет → «требуется команда».

### 3.4 Оценка потенциальной ценности

- **Алгоритм:** анализ размера рынка (если указан), числа упоминаний проблемы, наличия конкурентов.
- **Шкала:** `value_score ∈ [0, 1]`.

## 4. Блок 3: Поиск связей

### 4.1 Кластеризация пользователей по интересам

- **Алгоритм:** K-means кластеризация по вектору интересов (Sentence-BERT).
- **Результат:** группы пользователей со схожими интересами.
- **Частота:** пересчёт каждые 24 часа.

### 4.2 Матчинг потребностей с предложениями

- **Алгоритм:** поиск пользователей, у которых потребность X и предложение Y.
- **Пример:**  
  Пользователь А: «Ищу CTO»  
  Пользователь Б: «Я CTO, ищу стартап»  
  Результат: match A↔B

### 4.3 Поиск комплементарных экспертиз

- **Алгоритм:** поиск пользователей, чьи навыки дополняют друг друга.
- **Пример:**  
  Пользователь А: `[Solidity, Python]`  
  Пользователь Б: `[React, TypeScript]`  
  Результат: match A↔B (backend ↔ frontend)

### 4.4 Поиск ресурсов под идеи

- **Алгоритм:** поиск инвесторов по категориям идеи.
- **Пример:**  
  Идея: «децентрализованный арбитраж»  
  Инвесторы: те, кто инвестировал в похожие проекты или указал интерес к `defi`, `arbitration`.

### 4.5 Поиск командных ролей

- **Алгоритм:** анализ идеи на наличие «дыр» в команде.
- **Пример:**  
  Идея: «децентрализованный маркетплейс» → нужны: `[Solidity, React, DevOps, Product, Legal]`  
  Поиск пользователей с этими навыками → рекомендация.

## 5. Блок 4: Рекомендации

### 5.1 Формирование персонализированных рекомендаций

На основе всех предыдущих блоков формируется список:
- **Люди** (по интересам, потребностям, навыкам)
- **Идеи** (по новизне, сложности, ценности)
- **Ресурсы** (инвесторы, гранты, платформы)

### 5.2 Ранжирование по релевантности
score = w1interest_sim + w2need_match + w3expertise_match + w4value_score



Веса настраиваются через DAO.

### 5.3 Отправка уведомлений

- **In-app** (в интерфейсе)
- **Push** (если мобильное приложение)
- **Email** (по желанию пользователя)

### 5.4 Логирование и обратная связь

- Логируются: какие рекомендации были приняты/отклонены.
- На основе обратной связи веса корректируются.

# scanner.py — сканирование диалогов в реальном времени

import asyncio
from typing import List, Dict, Any
from datetime import datetime

class DialogScanner:
    """Сканирует диалоги и передаёт их на анализ."""
    
    def __init__(self, db_connection, message_queue):
        self.db = db_connection
        self.queue = message_queue
    
    async def scan_new_messages(self, user_id: str, messages: List[Dict[str, Any]]):
        """Обрабатывает новые сообщения в диалоге."""
        for message in messages:
            # Сохраняем сообщение в базу
            await self.db.save_message(user_id, message)
            
            # Отправляем на анализ в очередь
            await self.queue.publish({
                "type": "message_analyze",
                "user_id": user_id,
                "message": message,
                "timestamp": datetime.utcnow().isoformat()
            })
        
        # Триггерим пересчёт профиля
        await self.queue.publish({
            "type": "profile_recompute",
            "user_id": user_id
        })
    
    async def scan_all_users(self):
        """Фоновое сканирование всех пользователей (периодическое)."""
        users = await self.db.get_active_users()
        for user in users:
            messages = await self.db.get_recent_messages(user.id, limit=100)
            await self.scan_new_messages(user.id, messages)
